## 五、相关但独立的问题（同次对话）

- **角色外观变化（受伤 / 换衣）会不会新建角色资产？**
  - 代码行为：按**名字**匹配（`normalizeName` 只去括号内容与空白）。
    - 提取器若写「林巧」→ **合并到同一条**，但 `appearance` 会被新描述**覆盖**（原外观丢）。

    也不得据此新建角色；只登记角色的**基准外观**」。

# 附加需求（2026-10-10 同次提出）：抽卡 / 生声音 必须进 GPU 队列

## 实测事实（4080，2026-10-10 18:29）

- **抽卡是独立子进程**：`shim.py` 的 `hb_refmod_extract` 直接 `subprocess.run(extract_mod.py …)`，
  **不经过 ComfyUI 队列、不受 `_comfy_lock` 约束**。
- **用户连点 6 个角色的「生成卡」→ 6 个并发抽卡**（character-22~27，各含 launcher + worker 两个进程）：
  - 启动 18:20:37~18:20:43，到 18:29 **已跑 8.5 分钟仍无输出**（正常单张约 1 分钟 → **慢 8.5 倍**）
  - **GPU 利用率 100%、显存 15846/16376 MiB = 96.7%**（接近爆显存）
  - 队列 `queue_running/queue_pending` **均为空**（证明它不在队列里）
- **TTS（生声音）同理**：`hb_tts_voice` 走 `subprocess.run(COSY_PY cv_tts.py …)` 独立子进程，同样不进队列。

## 用户需求（2026-10-10 拍板）

> 「那这个生卡也得进队列」「还有生声音,也得进队列」

- **抽卡（图片卡 / 声音卡）必须进 ComfyUI 队列**，与生图/生视频串行，不许并发抢显存。
- **TTS（生成声音）也必须进队列**（或至少与 ComfyUI 任务互斥）。

## 可行方案（已核实节点存在）

**抽卡 → 改走 ComfyUI 节点（正解，天然进队列）**：`ComfyUI-MiniMaxH3Mod` 已提供
- `MiniMaxH3RefModExtract`（"Create H3 RefMod"）—— 图片/视频抽卡
- `MiniMaxH3RefModAudioExtract`（"Create H3 Audio RefMod"）—— 音频抽卡
- `MiniMaxH3RefModMasterExtract`（"Create H3 RefMod Master"）—— 视觉+音频一起抽
- `MiniMaxH3RefModSave`（"Save H3 RefMods"）—— 收尾保存

改法：`shim.py` 的 `hb_refmod_extract` / `hb_refmod_extract_voice` 从 `subprocess.run(extract_mod.py)` 改成
`POST http://127.0.0.1:8188/prompt` 提交节点图 → 由 ComfyUI 排队执行 → 轮询 `/history` 取结果。
**属 4080 侧改动（改 shim + 重启中转），不用重编 App 包。**

**TTS → CosyVoice 不是 ComfyUI 节点，进不了队列**：
- 方案 a：中转侧加**全局 GPU 锁**，并在取锁后**等 ComfyUI 队列空**再跑（简单、够用）。
- 方案 b：给 CosyVoice 写一个 ComfyUI 自定义节点，彻底并进队列（工作量大）。
