- **抽卡是独立子进程**：`shim.py` 的 `hb_refmod_extract` 直接 `subprocess.run(extract_mod.py …)`，
  **不经过 ComfyUI 队列、不受 `_comfy_lock` 约束**。
- **用户连点 6 个角色的「生成卡」→ 6 个并发抽卡**（character-22~27，各含 launcher + worker 两个进程）：
  - 启动 18:20:37~18:20:43，到 18:29 **已跑 8.5 分钟仍无输出**（正常单张约 1 分钟 → **慢 8.5 倍**）

- **TTS（生声音）同理**：`hb_tts_voice` 走 `subprocess.run(COSY_PY cv_tts.py …)` 独立子进程，同样不进队列。

## 可行方案（已核实节点存在）

改法：`shim.py` 的 `hb_refmod_extract` / `hb_refmod_extract_voice` 从 `subprocess.run(extract_mod.py)` 改成
`POST http://127.0.0.1:8188/prompt` 提交节点图 → 由 ComfyUI 排队执行 → 轮询 `/history` 取结果。
**属 4080 侧改动（改 shim + 重启中转），不用重编 App 包。**

**TTS → CosyVoice 不是 ComfyUI 节点，进不了队列**：

## 道具文字准确性需求（2026-10-10 用户提出，待拍板，**尚未实施**）

### 背景与实测事实
- **现象**（用户实测 sb302 视频）：道具近景的纸面文字与参考图不一致；纸会自己翻到背面；背面能隐约透出字，且透出的字「和参考图差不多」。
- **用户关键观察（推翻助手错误结论）**：**场景参考图里的字一直很准**（标语墙、厂牌），**只有道具图的字不准** → 说明**不是 H3 画不准字**，而是**这张道具图的形式有问题**。
- **道具图现状**：**三联板**（正面俯视 / 斜视 / 空白背面 三块拼在一张 1024×1024 图里）。
- **判定**：三联板把「同一张纸」画成「三个不同的东西」→ H3 分不清哪块是标准正面（可能拿了背面那块当参考）；且每块只占整图 1/3 像素 → 字更糊。**场景图是单一视角、字大且清晰 → 所以准**。

### 已定的动作（用户选 A，**待实施**）
- **重做道具参考图**：改成**单一正面视角**（字占满画面），与场景图形式一致。代价：翻到背面的镜头无参考（按用户口径「其他时候只要形状大小对」，可接受）。

### 待讨论的两个补充方案（用户正在权衡）
1. **提示词里写出文字内容**（如硬写「1975年3月17日」）
   - 优点：最明确。
   - 风险：**与参考图冲突**（已踩过坑：提示词写「第二车间」，而道具 `final_prompt` 是「红星机械厂二车间」；且提示词凭空多出一行「钳工学徒」）。**与既有规则「不把文字内容写进提示词，文字由 props.final_prompt/参考图管」直接矛盾。**
2. **提示词里明确要求「必须完全复现参考图中的字」**（不写内容，只下指令）
   - 优点：**不违反既有规则**（没写具体内容）、无冲突风险、指令明确。
   - 风险：能否照抄仍取决于参考图清晰度（故需与「单视角重做」配合）。
   - 拟定措辞（未实施）：
     - 中文：`@道具名上的任何文字、表格线与印章，必须与参考图中的完全一致，不得改写、增删或臆造。`
     - 英文：`Any text, table lines or seal on <Subject N> must match <Picture N> exactly — do not reword, add or invent.`

### 助手建议（待用户拍板）
- **方案 2 + 单视角重做 组合**：图先做清晰（单视角），再用提示词明确「必须完全复现」，**不写出内容**。这样既不违反既有规则，又给了模型明确指令。
