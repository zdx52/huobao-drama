## 一、已确认的实测事实

- **现行去重规则** = 「地点 + 时间段」**精确匹配**（`backend/src/agents/tools/extract-tools.ts` 的 `saveDedupScenes`）：
  同地点**不同时段** = **新场景**（规则原文：「场景：按【地点+时间段】精确匹配…同地点不同时段视为新场景」）。
- **实测 drama 4**：9 个场景 = 6 个地点。「二车间钳工台前」独占 **4 条**（清晨 / 上午 / 中午 / 下午），
  分别被 **4 / 3 / 4 / 5** 个分镜引用（合计 **16 / 33**，近一半分镜都在这 4 条里）。
- 场景是**剧级**资产（`scenes.drama_id`）；`scenes.episode_id` 字段存在但**实际为空**。
- 场景 `time` 字段（清晨/上午/…）在**生成参考图时并不参与**，参考图只用 `prompt` + `lighting`。

## 二、用户需求（2026-10-10 拍板）

## 五、相关但独立的问题（同次对话）

- **角色外观变化（受伤 / 换衣）会不会新建角色资产？**
  - 代码行为：按**名字**匹配（`normalizeName` 只去括号内容与空白）。
    - 提取器若写「林巧」→ **合并到同一条**，但 `appearance` 会被新描述**覆盖**（原外观丢）。
    - 提取器若写「受伤的林巧」→ **名字不同 → 新建一条**（出现两个林巧）。
  - **系统原设计**：外观变化**不该进资产**，应写进**分镜正文**（`video-prompt/SKILL` 已有此规则：
    「本段发生的外观变化（衣服湿透、沾油、换装、受伤、戴面具）必须写进正文，卡与锁块只管不变的基准」）。
